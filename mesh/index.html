Sending bitcoin (and XBT) over mesh networks: what actually works

Quick version

  1. Optional: this is for using bitcoin off-grid, after your XBT is in your own wallet.
  2. Sign offline, then relay the signed transaction over the mesh to a gateway with internet.
  3. We found no mesh tool that says it supports XBT yet.

You can’t run a blockchain over a radio mesh, but you don’t need to. Every working method uses the same trick: sign the transaction offline, carry the small signed message over the mesh to someone who has internet, and let that “gateway” broadcast it. Your keys never leave your device.

Where this fits: this is optional, for using bitcoin off-grid. Get your XBT into your own wallet first: Start here.

Short version (November 15, 2026): the Meshtastic relay projects work for bitcoin but are hobby-grade and experimental. TxTenna and goTenna Mesh are effectively discontinued. Bitchat can pass Cashu ecash (custodial tokens), not on-chain coins. We found no mesh tool that says it supports XBT.

The general method: sign offline, relay a raw transaction

  1. Build and sign the transaction on a device that isn’t online (a hardware wallet, or wallet software on an offline computer). The result is a “raw transaction”: a few hundred bytes written as hex.
  2. Chop it into pieces. Mesh messages are small. One Meshtastic bridge project notes Meshtastic’s apps cap a message at 228 bytes, while a raw transaction’s hex can run past 1,000 characters, so tools split it into numbered chunks.
  3. Send the chunks across the mesh to a gateway node, hop by hop. Relays in between just pass packets along.
  4. The gateway reassembles and broadcasts the transaction to its own full node (or a public service), which sends it to the network.

A signed transaction can’t be changed in transit without breaking its signature, so a relay can’t redirect your coins. A relay can drop it, delay it, or see it.

Source: MeshtasticBitcoinCore_Bridge README (message size); BTC Mesh README (chunking and reassembly).

Meshtastic relay projects (LoRa)

Meshtastic has no built-in bitcoin feature. A few community projects add one. All are small, Bitcoin-only and experimental:

ProjectWhat it doesStatus
BTC Mesh Relay (eddieoz)A client sends a raw transaction as chunked Meshtastic direct messages. A relay server with a Meshtastic radio reassembles it and submits it to a Bitcoin Core node over RPC, optionally through Tor. Command-line and GUI clients.README says “currently under development”. MeshtasticBitcoinCore_BridgeBroadcasts raw transactions sent over Meshtastic to a computer running Bitcoin Core, using manual message framing.Small project. Last push February 7, 2026.
btc-mesh (brh28)Python scripts for sending bitcoin transactions over a mesh network.Last push March 29, 2023, so treat it as unmaintained.

Hardware: any Meshtastic radio that connects to a computer or phone can carry the chunks. Radios with a USB connection to a laptop are the easiest fit for these Python tools, for example the Heltec WiFi LoRa 32 V4 dev board or the LILYGO T-Beam Supreme. A gateway runs best on a fixed node with good height and steady power. See the Meshtastic supported hardware list and getting started guide. A local mesh group can tell you whether anyone already runs a gateway.

goTenna Mesh and TxTenna

TxTenna was a proof-of-concept Android app from Samourai Wallet’s Mule.Tools project. It sent signed bitcoin transactions over goTenna Mesh radios (or SMS) to a gateway, which pushed them out through Samourai’s node.

  • The app: its GitHub repository was last updated April 24, 2020.
  • The gateway: on April 24, 2024, U.S. prosecutors charged Samourai’s founders, and Samourai’s web servers and domains were seized (U.S. DOJ, CoinDesk). We assume the default gateway no longer works; we haven’t tested it.
  • The radios: goTenna stopped supporting its consumer goTenna Mesh in 2024 and now sells only its Pro line, per a security researcher’s disclosure that also lists unpatched vulnerabilities. goTenna Mesh is not LoRa, so it can’t talk to Meshtastic radios.

Bottom line: interesting history, not something to rely on today.

Bitchat: ecash over Bluetooth

Bitchat is a phone app that relays messages over Bluetooth between nearby phones. Since July 7, 2026 (pull request #1376, shipped in v1.6.0) it can detect and send Cashu ecash tokens with a /pay command.

  • That is ecash, not an on-chain transaction. A token is a claim on a Cashu “mint” that holds the real bitcoin, so you are trusting that mint.
  • Tokens are bearer instruments: whoever redeems one first gets it. That’s why Bitchat asks you to confirm before paying in a public channel.
  • Bitchat doesn’t contact a mint itself. Redeeming hands off to a separate Cashu wallet, which needs internet at some point.
  • We found no Cashu mint for XBT.

More on the app: Bitchat and Meshtastic.

Blockstream Satellite: receiving, not sending

Blockstream Satellite broadcasts the bitcoin blockchain from satellites covering the Americas, Europe, Africa and Asia-Pacific. With a dish and receiver kit, a node can stay synced without internet (Blockstream help center). It’s one-way: it lets an off-grid node see payments and confirm them, but you still need a mesh relay (or other link) to send. The service was still running in 2026: Blockstream published a network frequency update on June 3, 2026. It carries the BTC (SHA-256) chain. We found nothing showing it carries XBT.

What about XBT?

None of the tools above documents XBT (BLAKE2b) support as of November 15, 2026. They all target bitcoin through Bitcoin Core or Samourai’s servers.

In principle, the raw-transaction method doesn’t care which chain a transaction belongs to. The chain is decided by the node at the gateway. A gateway that hands transactions to an XBT node (Bitcoin Knots with the BIP-110/BLAKE2b rules) instead of a Bitcoin Core node would broadcast on XBT. That is our reading of how these tools work, not something any project has tested or promised. If you try it, use tiny amounts.

Replay warning: if you sign from a wallet that held coins before the August 8, 2026 split, the same signed transaction may be valid on both chains, and whoever holds it could broadcast it on either. Split your coins first with our split guide, or sign with an XBT wallet that uses replay protection (SIGHASH_UNIFIED). See Set up Shrike.

Privacy and safety

  • Mesh traffic isn’t private by default. Relays and the gateway can see your raw transaction, which shows the addresses and amounts. On Meshtastic, use direct messages, and channel encryption where your group uses it. Don’t post transactions in a public channel.
  • The gateway operator sees the most. They can link your radio’s node ID to your transaction and could log it. Use a gateway you trust, or run your own. BTC Mesh can connect its node through Tor.
  • Radios reveal location. Many Meshtastic radios share GPS position. Turn off position sharing if you don’t want your transaction linked to a place.
  • Never send a seed phrase or private key over any mesh. Only signed transactions travel. No legitimate relay will ever ask for keys.
  • Test small, and check the transaction on a block explorer once you’re back online.
  • Follow your local radio rules. LoRa bands and power limits vary by country.
